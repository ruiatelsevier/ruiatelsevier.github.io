# Blog Side Panel Design

## Goal

Add a static blog navigation panel to the right side of blog archive pages and individual blog posts. The panel should help readers browse posts by publication year and by tag without adding JavaScript, new dependencies, or marketing-style page sections.

## Scope

In scope:

- Show a right-side blog archive panel on blog-related archive pages.
- Show the same panel on individual posts in the `posts` collection.
- Provide a year archive section that is expanded by default.
- Provide a tag archive section that is collapsed by default.
- Link years and tags to existing archive-page anchors.
- Keep the left author sidebar unchanged.

Out of scope:

- In-place filtering of post lists.
- Per-year or per-tag generated pages beyond the existing archive pages.
- Client-side routing or persistent UI state.
- Changes to non-blog pages such as CV, publications, talks, sitemap, and general pages.

## Architecture

Create a reusable Liquid include, `_includes/blog-side-panel.html`, that renders the blog navigation from Jekyll build-time data. The include should use existing site data sources:

- `site.posts` for publication years.
- `site.tags` for tag names and tag counts.

The include should be rendered in two places:

- `_layouts/archive.html`, guarded by a page front matter flag such as `blog_side_panel: true`.
- `_layouts/single.html`, guarded by `page.collection == "posts"`.

The panel should reuse the theme's right-sidebar concept through `sidebar__right`, with a more specific class such as `blog-side-panel` for scoped styling.

## Components

### Blog Side Panel Include

`_includes/blog-side-panel.html` renders:

- An accessible container labelled as blog archive navigation.
- A compact heading, for example `Blog Archive`.
- A native `<details open>` section for `By Year`.
- A native `<details>` section for `By Tags`.

Each year row links to the existing year archive page anchor:

```text
/year-archive/#2026
```

Each tag row links to the existing tag archive page anchor:

```text
/tags/#harness-engineering
```

Rows should show a count next to each label.

### Archive Layout

`_layouts/archive.html` should render the include only when the page opts in:

```yaml
blog_side_panel: true
```

The opt-in archive pages are:

- `_pages/year-archive.html`
- `_pages/tag-archive.html`

### Single Post Layout

`_layouts/single.html` should render the panel only for posts:

```liquid
{% if page.collection == "posts" %}
```

The panel should not appear on standalone pages that also use `single`.

### Styles

Add scoped styles for `.blog-side-panel` near existing sidebar styles in `_sass/_sidebar.scss`. The panel should be compact and quiet:

- Small heading.
- Plain text links.
- Muted count text.
- Light separators.
- No nested cards.
- No decorative sections.

If the existing page or archive content widths collide with the right panel, add a scoped class to `#main`, such as `layout--blog-side-panel`, and adjust only that layout state.

## Data Flow

At build time, Liquid reads `site.posts` and `site.tags`.

For years:

1. Iterate through `site.posts`.
2. Group posts by `post.date | date: "%Y"`.
3. Render years in reverse chronological order.
4. Count posts in each year.
5. Link to `/year-archive/#<year-slug>`.

For tags:

1. Iterate through `site.tags`.
2. Sort tag names alphabetically using the existing Liquid patterns where practical.
3. Count posts per tag.
4. Link to `/tags/#<tag-slug>`.
5. Omit the tag section if no tags exist.

The panel is regenerated by Jekyll whenever posts or tags change.

## Behavior

On archive pages:

- Clicking a year navigates to that year heading on `/year-archive/`.
- Clicking a tag navigates to that tag heading on `/tags/`.

On post pages:

- Clicking a year or tag leaves the article and navigates to the matching archive section.

This is intentionally link-based. It does not filter the current page in place.

## Accessibility

- Use semantic navigation markup, such as `<nav aria-label="Blog archive">`.
- Use native `<details>` and `<summary>` for collapsible sections.
- Ensure links have visible focus states through existing link styles or scoped additions.
- Do not rely on JavaScript to expose content.

## Testing

Run the normal Jekyll build for the site.

Manually verify in a browser:

- `/year-archive/` shows the panel.
- `/tags/` shows the panel.
- A representative post page shows the panel.
- Non-blog pages do not show the panel.
- Year links navigate to the matching year heading.
- Tag links navigate to the matching tag heading.
- Desktop layout has no overlap between content and right panel.
- Mobile layout remains readable and does not hide navigation content.

## Risks And Tradeoffs

- Link-based navigation is simpler and more reliable than in-place filtering, but it does navigate away from post pages.
- The current theme already has left and right sidebar conventions; the implementation should avoid broad layout refactors and only scope width adjustments to pages using this panel.
- Tag slug generation must match the existing tag archive heading IDs. Use the same `slugify` convention as `_pages/tag-archive.html`.
